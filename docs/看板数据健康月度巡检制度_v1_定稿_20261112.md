- 版本：v1.0　生效日：2026-12-01（11 月为基线月，已实测）

- 执行体：`tools/healthcheck/monthly_audit.py` + `.github/workflows/monthly_audit.yml`（每月 1 日 02:00 UTC 自动）
- 首轮实测：commit `e1c424e`，Actions run `43188269790`，89 项 → PASS 65 / WARN 19 / FAIL 3 / SKIP 2
- 证据：`tools/healthcheck/evidence/2026-11-12/`（JSON + MD + 3 张页面截图）

## 0. 一页摘要

**每月 1 日，用可复跑脚本把「每个指标还活着吗」和「页面上显示的是不是最新」同时验一遍，落证据；任何 critical 项不过，当月不算交付完成。**

三条铁律：
1. **只审线上那一份**（`https://bayoutree.github.io/macro-dashboard-/`），报告必须附 commit hash + run id。本地跑绿只证明本地。
2. **数据端 PASS ≠ 页面是新的**。页面显示值必须与源值逐卡比对，日期必须落在发布周期内。
3. **无证据 = 未巡检；FAIL 不许口头豁免**。要么修，要么改阈值留痕，要么主人批准降级。

制度要防的不是"代码写错了"，而是**代码端、数据端都正常，用户看到的页面还是旧数字**。近 3 个月 16 起故障里，9 起（发布断链 3 + 呈现失真 6）都是这个特征。

## 1. 三类失效（制度直接对着这三类设计）

| 类型 | 典型表现 | 数据层门禁能发现 | 对应层 |
|---|---|---|---|
| **A 源断/断更** | 上游改版、限流、停更，指标静默停在某天 | 能（若已登记 manifest） | L1 |
| **B 发布断链** | 仓库已更新，线上 Pages/CDN 还是旧的；双副本漂移；cache-buster 没 bump | **不能** | L2 |
| **C 呈现失真** | 取错字段、mock 兜底静默生效、"✅最新"常亮、注记重复、单位/口径错、裸标识符 | **不能** | L3 |

> 2026-11-11 主人截图 15 张，A/B/C 三类全部命中，而当天四个核心端点实测都是新鲜的——**门禁只覆盖核心端点，覆盖范围之外全是盲区**。

- **文件分级**：`tools/healthcheck/file_tiers.json`（Tier A 呈现指标 / B 中间产物 / C 归档），未登记即 `HC-D-REG` FAIL。
- **呈现登记**：`tools/healthcheck/render_registry.json`（卡片 DOM id → 源文件 + JSON 路径 + 容差），未登记卡片不计覆盖率。

## 3. 四层门禁

| 层 | 断言 | 工具 | 失败语义 |
|---|---|---|---|
| **L0 语法/构建** | js 语法、JSON 可解析 | `pre_push_check.sh` | 任一失败即 FAIL，禁止发布 |
| **L1 数据层** | 53 条逐项新鲜度（**期次口径**）+ 值层体检（空值写入/零值污染/序列停滞/量级异常）+ 文件分级对账 | `monthly_audit.py --offline` | critical STALE/GAP → FAIL |
| **L2 发布层** | ① 线上 Pages JSON ↔ 仓库 HEAD 逐文件 `as_of` + 字节一致 ② `data/` ↔ `frontend/data/` 双副本一致 ③ `index.html ?v=` == js 内容 sha1 ④ 前端引用文件存在 | `monthly_audit.py` + `monthly_consistency_check.py` | 线上落后仓库 → FAIL |
| **L3 呈现层** | 真实浏览器打开三页：DOM 显示值 ↔ 源值（容差）、徽标失真、mock 残留、占位符、裸标识符、Console 错误 | playwright + chromium | 值不等 → FAIL |

**L3 的三条判定必须同时满足**（这是主人要求的核心）：
1. 页面显示值 == 源值（超容差即 FAIL，无一例外）；
2. 页面"最新"日期落在该频率的正常发布周期内（超 2 个周期 FAIL，落后 1 期 WARN 并 3 日内定性）；
3. Console 真实错误 = 0。

## 4. 月度 SOP

| 时点 | 动作 | 角色 | 时限 |
|---|---|---|---|
| 每月 1 日 10:00 | CI 自动跑 `--strict`，产物存档 90 天 | 机器 | ~3 min |
| 1 日 12:00 前 | CIO 独立复跑 L1/L2（不复用松子输出）+ 复核 FAIL 定性（真断更/口径/误报） | CIO | 30 min |
| 1 日 18:00 前 | 出《月度巡检简报》：FAIL 清单 + 处置人 + 期限 | 松子 | 20 min |
| 3 日内 | FAIL 项修复，或申请"接受并降级"（需主人批准） | 责任人 | — |
| 5 日内 | 误报项改 manifest 阈值（**不许口头豁免**） | 松子 | — |
| 跨月 | 不得带病跨月；未修完列为"挂账"并说明 | CIO 裁决 | — |

**巡检 ≠ 修数据**：巡检只判定与留证，禁止脚本顺手改数据（避免"巡检把证据改了"）。

## 5. 六项裁决（CIO 定稿结论）

| # | 争议 | 裁决 | 理由 |
|---|---|---|---|
| **1** | FAIL 是否阻断当月交付 | **分级阻断**：<br>· critical（severity=block）FAIL → 阻断发布 + 阻断当月数据类交付<br>· 非 critical FAIL → 不阻断发布，进"待处置清单"，**60 天未处置升 FAIL**<br>· **G3 页面值≠源值：一律阻断，不看 critical** | 当前 CI 报 3 个 FAIL 全是 `critical=False` 的 warn 级指标（oecd_cli、legulegu×2），若一律阻断会红灯常亮→"狼来了"→制度失效；但页面显示错值是最严重问题，无例外 |
| **2** | `frontend/data/` 双副本 | **保留 30 天观察 → 零引用则删除**；期间强制一致性门禁 + `noindex` | 页面实际读 `data/`（js 引用已验证），副本属历史遗留可公开访问路径；直接删需先确认无外部引用 |
| **3** | `oecd_cli`（停 2023-11） | **标 deprecated（停更）**，摘出活跃指标，页面灰灯 + "源已停更"，不进 FAIL；每季度复评一次源是否恢复 | 源访问受限非我方故障，但不能假装有数据；每月红一次会污染巡检信号 |
| **4** | `legulegu` 两项（停 2026-09-11） | **2 周内换源，换不到则下线** | 已停 2 个月；破净率已有 akshare 自算链可替代，不宜长期挂红 |
| **5** | 值断言覆盖率 60% | **改为 100% 核心卡（12 张）**，分三步：12 月 6 张 → 1 月 9 张 → 3 月 12 张 | 核心卡本就只有 12 张，60% 无意义；直接做全 |
| **6** | 口径责任边界 | manifest 阈值由**松子维护**（懂链路），CIO **复核 + 定性误报**；争议由主人裁决；误报 24h 内定性 | 分工与现有协作机制一致 |

**核心卡 12 张清单**（值断言目标）：恐贪指数、择时综合分、周期定位、股债性价比(ERP)、A股情绪、融资余额、美债10Y、VIX、美元人民币、破净率、股息率利差、联邦基金利率。

## 6. 硬性门禁条款（G1–G15，全部可机检）

| 编号 | 条款 | 判定 |
|---|---|---|
| G1 | critical 指标任一 STALE/GAP，当日不得发布 | FAIL |
| G2 | 连续落后：日频 3 交易日 / 周频 2 周 / 月频 2 期 / 季频 2 季 | FAIL（非 critical 记待处置） |
| G3 | 页面显示值 ≠ 源值（超容差） | **FAIL，无一例外** |
| G4 | 「✅最新」超 2 个周期仍亮 → FAIL；落后 1 期 → WARN + 3 日内定性 | FAIL/WARN |
| G5 | 线上 `as_of` 落后仓库 → FAIL（发布未完成，不得宣称已交付） | FAIL |
| G6 | `value=null` 或 `value=0` 而历史非零 → FAIL（空值/零值禁止落库） | FAIL |
| G7 | 页面可见 mock 硬编码时间戳（真实数据未覆盖） | FAIL |
| G8 | 新增 `data/*.json` 未登记 Tier / 新增数值卡未登记 render_registry | FAIL/WARN |
| G9 | 指标节点缺 `source` / `caliber`（当前 3 处 M1 待补） | FAIL |
| G10 | 页面出现 snake_case 裸露标识符（当前 2 处：`fai_yoy_cum`、`timing_scores`） | FAIL |
| G11 | **月/季频必须用"应已发布最新期"口径**，禁止用期初日期算自然日差 | 口径 |
| G12 | FAIL 项 24h 内定性；误报必须改 manifest 阈值并留痕 | 流程 |
| G13 | 每次巡检必须落 JSON+MD+截图+commit hash；无证据 = 未巡检 | 流程 |
| G14 | 同一 FAIL 连续 2 个月未处置 → 升级项目级阻塞，不得进下月排期 | 流程 |
| G15 | 值层体检（量级/单位/序列停滞）WARN 级，同类重复出现升 FAIL | WARN→FAIL |

> **G11 是本轮最重要的方法论**：`2026-09-01` 这类期初日期若按自然日算会系统性误报一个月，制造假红灯，消耗信任。首轮据此修正 3 例误报。

### 6.1 建议同步升级（不在本制度范围，强相关）
- `update-data.yml` 中 `freshness_gate` 从"只告警"改为"critical FAIL 即阻断提交"。
- `run_all.py` 单脚本失败必须产生可推送告警（当前只写日志，这是断更被静默放大的机制原因）。
- 数据版本回退门禁：新文件 `as_of` 早于线上 `as_of` 时禁止提交（F12 类事故根治）。

| # | 现象 | 类型 | 现有机制能否发现 | 制度对应 |
|---|---|---|---|---|
| F1 | 恐贪断更 8 天 | A | 部分 | G1/G2 |
| F2 | 融资买入占比 `value=0.0` 页面显示 0.00% | C | 不能 | G6 |
| F3 | 全A换手率停 1 个月（东财限流簇） | A | 部分（warn 不阻断） | G2 |
| F4 | 中位数PE 停 4 周 | A | 同 F3 | G2 |
| F5 | 财政支出增速停 2026-08 | A | 部分 | G8 未登记即盲区 |
| F6 | 全球周期 v4 全模块冻结 8~9 月 | A | 不能（不在 manifest） | G8 |
| F7 | "✅最新"在 8~9 月旧数据上常亮 | C | 不能 | G4 |

| F10 | "更新于 2026-10-08" vs 图尾 11-06 错位 | C | 不能 | L3 日期一致性 |
| F11 | 70城房价同比显示 100.0% | C | 不能 | G15 量级体检 |
| F12 | 强推覆盖已采数据（多文件回退） | B | 不能 | G5 + 6.1 回退门禁 |
| F13 | `data/` 与 `frontend/data/` 漂移 | B | 部分 | L2 双副本门禁 |
| F14 | 社融连挂 4 天 | A | 不能 | 6.1 告警升级 |
| F15 | CDN 缓存致页面不更新 | B | 不能 | L2 `?v=` 校验 |
| F16 | 桩值/降级数据夹带进正式文件 | C | 部分 | G7 |

**五条规律**：① 断更几乎都在 manifest 覆盖外；② 静默是主因不是源坏；③ 值层面的脏数据比日期断更更危险；④ 呈现层缺陷占比最高（5/16）；⑤ 工程链事故会把好数据弄坏。

## 8. 台账与升级

台账：`看板维护/月度巡检/问题台账.md`，字段 `ID | 发现日 | 层 | 指标 | 现象 | 根因 | 修复 commit | 复发次数 | 状态`

- 只增不删，关闭须注明验证方式。
- 同一问题**第 2 次**发生 → 必须新增自动门禁，否则记"未修复"。
- 同一指标**连续 2 个月** FAIL → 升级结构性缺陷（改架构/换源，不再补数据）。

## 10. 已知限制（必须写进制度，避免把 SKIP 当 PASS）

1. **无浏览器环境时 L3 整体 SKIP**，报告写 SKIP 不写 PASS。本地 macOS 沙箱当前无法启动 Chromium（实测 SIGABRT），L3 依赖 CI 或装有 playwright 的机器。
2. 值级断言当前仅 5 张卡，覆盖率低；按裁决 5 分三步提升至 12 张。
3. 期次口径依赖 `lag_days` 准确性，写错会误报/漏报（首轮已修 3 例）。
4. `frontend/data/` 副本可独立访问，存在被误用风险（裁决 2 处理）。
