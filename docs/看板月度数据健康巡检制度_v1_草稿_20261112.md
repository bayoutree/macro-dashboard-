## 0. 一句话

每月固定一天，用可复跑的脚本把「**每个指标是否还活着**」和「**页面上显示的是不是最新的**」同时验一遍，产出可留档的证据；任何一项不过，当月就不算交付完成。

制度要防的不是"代码写错了"，而是**代码端、数据端都正常，用户看到的页面还是旧数字**。近 3 个月 16 起故障里，有 11 起属于这一类。

## 1. 三类失效（制度直接对着这三类设计）

| 失效类型 | 典型表现 | 数据层门禁能发现吗 | 本制度对应层 |
|---|---|---|---|
| **A. 源断/断更** | 上游改版、限流、停更，指标静默停在某天 | 能（若该指标在 manifest 里） | L1 数据层 |
| **B. 发布断链** | 仓库已更新，线上 Pages/缓存还是旧的；双副本不同步；cache-buster 没 bump | **不能** | L2 发布层 |
| **C. 呈现失真** | 值取错字段、mock 兜底静默生效、"✅最新"常亮、注记重复、单位/口径错 | **不能** | L3 呈现层 |

历史教训很直接：2026-11-11 主人截图 15 张，A/B/C 三类全部命中，而当天四端点（timing_scores / dashboard_summary / feargreed / indicators）实测都是新鲜的——**门禁只覆盖了核心端点，覆盖范围之外全是盲区**。

### 2.2 指标清单（快照，以 `data/freshness_manifest.json` 为唯一真值）

- manifest 共 **53 条**：51 条 active + 2 条 deprecated（孤儿文件，标 report 不评估）
- 数据文件 **39 个**，本轮已全部登记进 Tier A/B/C（见 §5.3）
- 每条指标登记了：`file` / `date_path` / `freq` / `lag_days` / `fresh_max_*` / `watch_max_*` / `critical` / `severity_on_gap` / `note`（含上游来源与口径）

**制度不复制这张表**（易变），只要求：**任何指标上线呈现前必须在 manifest 登记，未登记即视为未纳入监控，页面不得展示**。当前清单见附录 A。

### 2.3 已有检测能力盘点（制度的地基）

| 机制 | 覆盖什么 | 缺口 |
|---|---|---|
| `scripts/freshness_gate.py` | manifest 全量新鲜度、结构、点数、双副本一致性 | 默认只告警不阻断；月/季频用自然日口径→系统性误报 |
| `scripts/history_guard.py` | 删史/缩史防线 | 只防"变少"，不防"变旧/变空" |
| `scripts/ssot_check.py` | 单点真值 + 镜像回写 | 需人工触发 |
| `tools/browser-smoke/data_layer_check.py` | 数据层断言 + headless DOM 存在性 | 断言"元素在"，不断言"值对不对" |
| `tools/browser-smoke/regression.py` | 页面可打开、结构文本存在 | 同上，无值级比对 |
| `.github/workflows/update-data.yml` | 每日跑批 + 提交 | 失败只红一次，次日若无告警就没人知道 |

**结论：现有机制能证明"文件更新了"，不能证明"页面显示对了"。这就是制度要补的那一段。**

### 3.1 从清单里提炼的 5 条规律

1. **断更几乎都发生在 manifest 覆盖范围之外**（F5/F6）——监控覆盖 ≠ 页面覆盖。
2. **静默是主因，不是源坏**（F1/F3/F4/F14）——`run_all.py` 设计上"单脚本失败不阻塞"，失败无升级路径。
3. **值层面的脏数据比日期层面的断更更危险**（F2/F11/F16）——日期新鲜、值是假的，所有基于日期的门禁全绿。
4. **呈现层缺陷占比最高**（F7~F11，5/16）——因为呈现层从来没有值级断言。
5. **工程链事故会把好数据弄坏**（F12/F13/F15）——发布与缓存是"数据端正常但页面不新"的最大来源。

## 4. 月度巡检 SOP

### 4.1 时点与角色

| 时点 | 动作 | 角色 | 时长 |
|---|---|---|---|
| 每月 1 日 10:00（自动） | CI 跑 `monthly_audit.py --strict`，产物存档 90 天 | 机器 | ~3 min |
| 1 日 12:00 前 | 复核 FAIL 项，定性：真断更 / 口径问题 / 误报 | 松子（代码侧）+ CIO（口径侧） | 30 min |
| 1 日 18:00 前 | 出《月度巡检简报》：FAIL 清单 + 处置人 + 期限 | 松子 | 20 min |
| 3 日内 | FAIL 项修复或明确"接受并降级"（需主人批准） | 责任人 | — |
| 5 日内 | 误报项修 manifest 阈值（**不许口头豁免**） | 松子 | — |

### 4.2 三条铁律

1. **无证据 = 未巡检**：必须落 JSON + MD + 截图，报告内附 commit hash 与 run id。
2. **FAIL 不许口头豁免**：要么修，要么改阈值并留记录，要么主人批准降级；三者之外不接受"知道了"。
3. **同一 FAIL 连续两个月未处置 → 升级为项目级阻塞**，不得进入下月迭代排期。

### 4.3 巡检 ≠ 修数据

巡检只做判定与留证。修数据走常规工单；**禁止巡检脚本顺手改数据**（避免"巡检把证据改了"）。

## 5. 自动化方案（已实现，可复跑）

### 5.1 三层结构

| 层 | 断言内容 | 依赖 | 失败语义 |
|---|---|---|---|
| **L1 数据层** | 53 条指标逐条新鲜度（期次口径）+ 值层体检（空值写入/零值污染/序列停滞/量级异常）+ 数据文件分级对账 | 离线 | critical STALE/GAP、值污染 → FAIL |
| **L2 发布层** | 线上 Pages 实际服务的 JSON ←→ 仓库 HEAD，逐文件比 `as_of` 与语义内容 | 网络 | 线上落后仓库 → FAIL（发布未完成） |
| **L3 呈现层** | 真实浏览器打开页面，DOM 显示值 ←→ 源值（容差比对）；徽标失真；mock 兜底静默；占位符；裸标识符；console 错误 | playwright+chromium | 值不等/徽标超 2 周期/mock 残留 → FAIL |

### 5.2 用法

```bash
python3 tools/healthcheck/monthly_audit.py --strict            # 标准动作（线上真实页面）
python3 tools/healthcheck/monthly_audit.py --offline --strict  # 无网络时只跑数据层
python3 tools/healthcheck/monthly_audit.py --serve-local       # 发布前预检
python3 tools/healthcheck/monthly_audit.py --eval-date 2026-10-31 --strict   # 复盘
```

退出码 `0/1/2`；产物 `tools/healthcheck/output/monthly_audit_<时间戳>.json|md` + `screenshots/*.png`；留档复制到 `tools/healthcheck/evidence/<日期>/` 并提交。

### 5.3 两张登记表（新增内容的强制入口）

- `tools/healthcheck/render_registry.json`：**呈现层断言登记**。卡片 DOM id → 源文件 + JSON 路径 + 容差。未登记卡片不计入覆盖率。
- `tools/healthcheck/file_tiers.json`：**数据文件分级**。Tier A = manifest 指标；Tier B = 中间产物（验存在+可解析）；Tier C = 回测/日志/归档。未登记 → `HC-D-REG` FAIL。

> 首轮就抓到 28 个未登记数据文件（含 `nbs_inventory_raw.json` 这类当日新增），已全部分级入册。**这就是"新指标偷偷上线、监控不知道"的入口闸门。**

### 5.5 已知限制（必须写进制度，避免把 SKIP 当 PASS）

1. **无浏览器环境时 L3 整体 SKIP**，报告里是 SKIP 不是 PASS。本地 macOS 沙箱当前无法启动 Chromium，L3 只能跑在 CI / 有 playwright 的机器上。
2. 值级断言目前只覆盖 5 张卡（USDCNY / 美债10Y / 联邦基金 / 破净率 / 股息率利差），**覆盖率远低于全部数值卡**。制度要求逐月提升，目标是核心数值卡 60%。
3. `frontend/data/` 是第二份可公开访问的副本（`/frontend/index.html` 也 200）。当前页面实际读 `data/`，但副本存在被误用的风险，需 CIO 确认是删除还是加 noindex。
4. 月/季频的"期次口径"依赖 `lag_days` 准确性，`lag_days` 写错会变成误报或漏报（本轮已修 3 例误报）。

## 6. 硬性门禁条款（建议写入制度正文）

> 全部条款可机检，标注对应检查编号；`--strict` 为月度巡检标准模式。

| 编号 | 条款 | 判定 | 机检 |
|---|---|---|---|
| **G1** | critical 指标任一 STALE/GAP，当日不得发布 | FAIL | `HC-D-*` |
| **G2** | 连续落后：日频 3 个交易日、周频 2 周、月频 2 期、季频 2 季 → FAIL（不是 WARN） | FAIL | `HC-D-*` |

| **G5** | 线上数据 `as_of` 落后仓库 → FAIL（发布未完成，不得宣称已交付） | FAIL | `HC-P-*` |
| **G6** | `value=null` 或 `value=0` 而历史非零 → FAIL（空值/零值禁止落库） | FAIL | `HC-D-*-v` |
| **G7** | 页面可见 mock 硬编码时间戳（真实数据未覆盖）→ FAIL | FAIL | `HC-R-*-mock` |

### 6.1 建议同步升级（不在本制度范围，但强相关）

## 7. 常见问题速查（症状 → 首查 → 处置）

| 症状 | 首查 | 常见根因 | 处置 |

| 页面数字停在某天 | `HC-P-*` 线上 vs 仓库；再看 cache-buster | 发布未完成 / CDN 缓存 / 双副本漂移 | 重跑部署；bump `?v=`；同步副本 |
| 卡片显示 0 / 0.00% | `HC-D-*-v` | 上游返回空被写成 0 | 加空值拦截 + 回填历史 |
| 卡片显示 "--" 或"待获取" | 该卡源文件字段 | 采集失败 / 字段改名 | 修采集；必要时标灰灯 |
| 数据显示"最新"但明显是旧值 | `HC-R-*-badge` | 徽标基准用数据自身日期 | 改为真实今天判定 |
| 同一段文字重复出现多次 | 渲染函数是否幂等 | 追加式渲染 | 重绘前清空容器 |
| 标题出现英文 snake_case | `HC-R-*-raw` | 中文化映射漏项 | 补映射 |
| 数值量级明显不对（100% 房价同比） | `HC-D-*-v` 量级体检 | 指数/涨跌幅口径混淆 | 改口径并回补历史 |
| 某指标"好久没动静" | manifest 是否登记 | 未登记 = 无监控 | 登记 + 定 freq/lag |
| 页面报错但数据是新的 | `HC-R-*-err` console | 前端 JS 异常导致渲染中断 | 修 JS；加 console 断言 |
